## Input, command and trust

The future Python3.12 stdlib command is `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tools python3 -B -m htfp_launch_manifest DOSSIER.json`. It reads exactly one explicitly named regular local JSON file and prints one JSON report plus LF to stdout. No stdin/default dossier, URL, fetch, apply, output-file, wallet, builder, network or service mode exists. Invalid arguments, including help probes, give CLI_USAGE/exit2. Normal errors have no traceback or stderr. Operational runtime failures outside the contract must fail visibly rather than emit a success report.

Open the explicit path read-only/nonblocking, then fstat the opened descriptor before any data read. Reject nonregular FIFO/socket/device/directory inputs as INPUT_UNREADABLE without blocking; close every descriptor. A symlink may resolve to a regular opened target. Read at most65537 bytes, reject more than65536, require strict UTF-8 JSON without BOM. Reject duplicate object keys, nonfinite constants and every JSON numeric literal; quantities/counters use canonical decimal strings. JSON booleans retain their type. Reject unpaired Unicode surrogates in every decoded string/key as INVALID_TEXT at `$` before UTF-8 length encoding or field traversal; valid escaped pairs decoding to a Unicode scalar remain ordinary text. Maximum nesting depth4 counts root container as1 and every nested container as another level. Text is nonempty, at most512 UTF-8 bytes, without C0 controls or DEL. At most16 assertions are allowed. Unknown keys at every object level are invalid. Output is bounded to131072 bytes. These are engineering input limits, not economic bounds.

The root schema is exactly `HTFP_LAUNCH_DOSSIER_V1`. Optional nullable groups are identity, mint, allocation, funding, market and volume; their exact leaf fields/types are in REQUIREMENTS. An absent/null group means all its fields are missing. Every leaf is optional/nullable; absent and null have the same missing-choice meaning. No supplied leaf is synthesized from a test profile or filled with a policy value. Missing assertions means no attributed assertions, not verification. An incomplete example uses confirmed policy literals only and null for unselected inputs; this is not selection of actual public state.

u64 strings are `0` or `[1-9][0-9]*`, ASCII only,1..20 digits, value<=18446744073709551615. No whitespace, signs, leading zeroes, exponent, decimal or coercion. Fractions are exactly `{numerator:u64,denominator:u64}` with positive denominator; they need not be reduced. Do not invent alpha<=1, positive alpha/rate/capacity, a fundraising minimum or an approved prestart interpretation. Pubkeys are canonical Base58 encodings of exactly32 bytes; this checks syntax only, not curve/signability/control/ownership. SHA256 is64 lowercase ASCII hex characters. Other text values can differ from confirmed policy and then cause a policy contradiction rather than a structural parsing error.

Optional assertions are a bounded list of `{subject,claim,citation?,claimed_status?}` text fields; subject/claim are required and nonnull, optional fields may be null. A supplied assertion missing either required field is TYPE_MISMATCH at that item; an incomplete nonnull fraction object is TYPE_MISMATCH at the fraction path. All such entries remain attributed unverified assertions. References are opaque strings: never open them, resolve URLs, load external files, or treat a hash, `approved`, `verified` or a citation as proof. No environment/cluster selector exists; the tool neither remaps Testnet HTFP/reserve to Devnet nor validates the external Devnet study as a deployment plan.

The checker embodies frozen reviewed rules and reports their four financial-source hashes. It does not reread those documents at runtime, interpret their prose dynamically, or establish that current public state matches them. Approval/source hashes are implementation/review provenance, not a production authorization certificate.

## Documentary checks

Each of the31 fixed checks in REQUIREMENTS compares a provided intended value with its source-backed literal. Missing/null gives MISSING; equality gives MATCH; inequality gives POLICY_MISMATCH. This is a comparison of statements only. The expected authority tokens NONE and CODE_RESTRICTED_PDA describe intended final powers; they do not invent or authenticate an actual authority address or prove revocation. H/reserve preserve D33 intended identity/attestation. New mint/initializer/genesis/metadata/extensions stay open regardless syntactically valid supplied candidates.

Run these seven relationship checks separately, preserving all applicable contradictions and open issues:

1. **ALLOCATION_TOTAL:** sum only the explicitly provided pool/LGE/team/marketing base-unit values against fixed nominal10000000000000000000. Sum>nominal always contradicts. Otherwise report known sum and exact unallocated-from-provided; a missing leaf is never filled with zero in the input. A below-nominal explicitly partial draft is PARTIAL_ALLOCATION, not a completed-allocation failure. `complete=true` asserts data completeness only, not founder approval: require all four amounts; missing ones cause COMPLETION_MISSING_AMOUNTS. With all four supplied, a shortfall causes COMPLETED_ALLOCATION_SHORTFALL. `complete=false` or null/absent never asserts completed allocation. The fixed pool35% and final distribution-wallet zero checks remain separate; the three non-pool amounts and recipients/entitlements/remainders remain provisional/open even when totals agree.
2. **FUNDING_TOTAL:** if all three values exist, require pool+reserve=gross raised. Neither maintenance, transaction costs, backing V nor observed reserve balances substitute for these intended D39 allocations. Do not infer raised funds or a remainder destination. Zero+zero=zero is arithmetic only, never proof of funding or a new minimum.
3. **FUNDING_RATIO:** from explicit N=raised derive exact fractions4N/5 andN/5. If N is divisible by5, compare each supplied leg with its exact integer share; mismatching legs each produce FUNDING_RATIO_MISMATCH. If N is not divisible by5, exact integer shares are impossible: emit one ROUNDING_UNRESOLVED open item, retain exact fractions and supplied-leg differences, and choose no rounding rule, tolerance or destination. This does not approve any supplied allocation, even a large departure; the ratio remains unevaluated pending policy. Conservation is independently checked and can still contradict. A supplied rounding-rule reference stays an unapproved choice and never closes this question. If N is absent, ratio evaluation is MISSING.
4. **ACTIVATION_EPOCH:** whenever scheduling E exists, derive E+2 and require it to fit u64. Overflow is EPOCH_RELATION_OVERFLOW even if activation is missing, because no u64 activation can satisfy it. Otherwise, if activation also exists, inequality is ACTIVATION_EPOCH_MISMATCH. Missing E, or missing activation without overflow, gives MISSING. Claimed epochs are unverified; never derive epoch duration, actual activation time, extra hours or a guaranteed timestamp from them.
5. **LP_LOCK_FRACTION:** require numerator=denominator for a supplied valid fraction. Its basis is100% of LP actually received for the initial contribution. It is not minimum liquidity, whole escrow, later/third-party deposits, an HTFP burn or a bytecode permanence proof. No LP amount is generated.
6. **PERSONAL_WALLET_MATCH:** compare the two supplied canonical public personal-wallet keys for equality. They are not HTFP token-account/ATA addresses. Syntax/equality establishes no person/control/creator authority, Fee Key ownership, claim routing or tax receipt. Those remain external gates.
7. **INITIAL_CREDIT_CAPACITY:** if both candidate values exist, require A0<=C as internal shared-credit consistency. Nothing selects the volume structure, numerical constants, positive values, timeframe or start/prestart policy. Alpha>1 and zero rate/capacity remain typed provisional candidates; they are not silently accepted production policy or rejected under an invented rule.

Input consistency and external truth are orthogonal. Every well-formed report retains seven external gates listed in REQUIREMENTS, including M5_FINAL_TARGET_ACCEPTANCE. The known counterexample, full107case gap and final500ppm target gate remain unresolved under the retained M5 disposition. M3/M4B/M6A local evidence neither resolves those gates nor proves public equivalence. Do not resume any deferred task.

## Exact report and errors

Report keys and fixed values are enumerated in REQUIREMENTS. All integer quantities, counts derived from dossier fields and rational components are strings; booleans/null retain their types. `policy_sources` is exactly the four financial-document paths mapped to their frozen SHA256 values. It is a reference to the embodied rule version, not an active source-file/public verification result. `input_sha256` hashes all exact input bytes if the entire file is read within the bound, even for invalid JSON; it is null for usage/unreadable/nonregular/oversized input.

`production_readiness=NOT_ASSESSED`, `public_verification=NOT_PERFORMED` and `approval=NOT_ESTABLISHED` are unconditional. Outcomes/exits are INPUT_INVALID/2, CONTRADICTIONS_PRESENT/1 or NO_DOCUMENTARY_CONTRADICTION_FOUND/0. Exit0 makes no assertion of completeness, readiness or approval; open and unverified items remain explicit. Input errors produce no partial assessment: checks, contradictions, open_items, unverified_assertions and derived are empty; the fixed error object is populated. Other reports have error=null.

Error phase order is CLI/read/size -> strict UTF-8/JSON parsing -> Unicode scalar validation -> nesting and collection bounds -> root/schema -> unknown/type/domain fields. Parser hooks reject the first duplicate/nonfinite/numeric-literal event encountered; ordinary syntax/decoder failures use INVALID_JSON and recursion-depth failure uses NESTING_LIMIT. An invalid encoding uses INVALID_UTF8. Do not promise an alternate ordering for multiple simultaneous parser defects. At each parsed object, unknown keys are checked before declared children; declared fields are traversed lexicographically and assertion items by input index. Fraction members are validated before denominator positivity. Root/schema failure precedes field checks. Unknown-field errors name their nearest declared parent path, never echo an arbitrary unknown key. All whole-input/parser/CLI errors use path `$`; schema errors use `schema`. All error messages are the fixed catalog; no OS details or traceback.

Findings are exactly `{code,path,source_ids,message}`. Fixed source IDs, paths, codes and messages are in REQUIREMENTS. For every missing/null leaf emit one MISSING_INPUT open item. MISSING_INPUT, OPEN_CHOICE and PROVISIONAL_CHOICE always use exactly the leaf top-level group's group_source_ids array, in its listed order; no fixed-field or relationship source-ID override applies. POLICY_MISMATCH continues to use its fixed field source IDs, and relationship findings use their relationship source IDs. For each supplied candidate listed in open_choice_paths/provisional_choice_paths emit OPEN_CHOICE/PROVISIONAL_CHOICE even if a caller asserts approval. These items can coexist with relationship contradictions. No unlisted production-choice promotion occurs. `allocation.complete` is a documentary assertion, not an open allocation-policy approval. Unknown assertions produce no new policy rule.

`checks` contains31 fixed-policy entries sorted by field path, then the seven relationships in the stated order. Each is `{rule_id,path,result}`; fixed rule_id is its field path. A relationship with missing necessary operands is MISSING, except allocation can assess any provided amounts: no amounts means MISSING unless complete=true triggers completion contradiction; a non-overallocated partial shortfall gives OPEN; complete/all supplied/exact total gives MATCH. Allocation with any contradiction gives CONTRADICTION; complete=false with nominal sum gives MATCH. Ratio with N%5!=0 is ROUNDING_UNRESOLVED; with representable N but missing either leg it is MISSING unless a supplied leg contradicts. Contradictions take precedence within a relationship. Fixed checks do not gain extra entries for candidate fields.

The seven relationship `checks[].path` values are frozen by each REQUIREMENTS `relationship_checks[].report_path`: ALLOCATION_TOTAL=`allocation`; FUNDING_TOTAL=`funding`; FUNDING_RATIO=`funding`; ACTIVATION_EPOCH=`mint`; LP_LOCK_FRACTION=`market.initial_received_lp_lock_fraction`; PERSONAL_WALLET_MATCH=`market`; INITIAL_CREDIT_CAPACITY=`volume`. These check-entry paths are separate from individual contradiction/open-item finding paths, which retain the existing finding_paths mapping.

Sort contradictions and open_items by `(path,code)`. External entries are seven fixed EXTERNAL_GATE_UNVERIFIED findings in REQUIREMENTS order, then one ATTRIBUTED_ASSERTION_UNVERIFIED per input assertion in input order, path `assertions[index]`. No assertion text/URL/claimed status is echoed into fixed messages; the original dossier and its digest preserve attribution. External finding paths are the named gate IDs. All messages are fixed; actual numerical differences are provided only in derived.

`derived` contains only these optional keys when their operands exist:

| Key | Exact meaning |
| --- | --- |
| allocation_known_sum_base_units | Sum of explicitly provided four-category amounts; omit if none provided |
| allocation_unallocated_from_provided_base_units | Nominal−known sum, if known sum<=nominal; not assigned to any recipient |
| allocation_overallocated_base_units | Known sum−nominal, only if positive |
| funding_sum_lamports | Pool+reserve, if both provided |
| funding_expected_pool_lamports | `{numerator:4*N,denominator:5}` if N provided; unreduced decimal strings |
| funding_expected_reserve_lamports | `{numerator:N,denominator:5}` if N provided; unreduced decimal strings |
| funding_pool_difference_numerator | 5*supplied_pool−4*N if both available; denominator5 implicit |
| funding_reserve_difference_numerator | 5*supplied_reserve−N if both available; denominator5 implicit |
| activation_expected_epoch | E+2 whenever E exists, including an overflow value that causes contradiction |

The two difference numerators may use canonical signed strings (`0` or optional minus before nonzero ASCII digits); other derived values are nonnegative decimal strings. Derived wide sums/products use exact integers and may exceed an input u64 without truncation. Nothing computes participant entitlement, an approximate rounded allocation, slot/epoch duration, live balances, price, AMM outputs or recommended volume. A completely supplied valid dossier still has unresolved production-choice/external findings under this frozen rule version.
